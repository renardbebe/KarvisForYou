## 待办"都做完了"不识别修复（已完成 ✅）
**问题**: 用户回复"都做完了"时，AI 没有理解为全部标记完成
**根因**:
1. Prompt 中只有 keyword(单条匹配) 和 indices(序号匹配)，没有"全部完成"的场景
2. Skill 层 `todo.done` 的 `complete()` 函数不支持"全部完成"模式

**修复内容**:
1. `skills/todo_manage.py`: 添加 `all` 参数支持，`all=true` 时将所有一次性待办移至已完成，循环待办打卡
2. `prompts.py`: Skill 描述增加 `all?` 参数说明；决策规则增加"都做完了/全部搞定/全做完了"→`all: true` 的明确指引
3. 特别添加上下文提示：当用户刚被提醒待办后回复"做完了"，应理解为全部完成
4. 已部署到服务器，容器 healthy

## Prompt 架构重构：从穷举规则到语义推理（已完成 ✅）
**问题**: Prompt 过度依赖触发词穷举（"做完了/搞定了" → todo.done），LLM 变成关键词匹配引擎，遇到规则外的说法就无法正确路由

**改造思路**: 从"穷举模式匹配"升级为"语义意图声明 + 推理引导"

**修改内容**（全部在 `prompts.py`）：
1. **RULES_CORE 头部新增「通用推理原则」**：明确告诉 LLM 它是智能助手而非关键词引擎，引入"决策三步法"（理解意图→匹配能力→推理参数），强调上下文是最强信号
2. **全部 RULES 分段重写**：每个模块从"触发词→Skill"改为"意图描述 + 边界约束 + 参数推理指引"
   - RULES_CORE: 待办管理/设置/归档/记忆等
   - RULES_HABITS: 习惯实验/Top3
   - RULES_ADVANCED: 决策复盘/语音日记/深潜/Agent Loop
   - RULES_BOOKS_MEDIA: 读书/影视笔记
   - RULES_FINANCE: 财务管理
   - RULES_SKILLS_MGMT: Skill 开关管理
3. **OUTPUT_FORMAT 的 thinking 字段升级**：从"一句话推理"改为「意图→... 匹配→...」格式，要求 LLM 先推理意图再选 skill
4. **保留了关键边界约束**：循环 vs 一次性提醒的区分、nickname vs ai_name 的方向区分等容易混淆的地方仍有明确规则

**预期效果**: "搞定啦""弄完了""OK了""都处理好了"等规则外说法，LLM 也能从语义理解正确路由到 todo.done

## Prompt Token 优化（已完成 ✅）
**目标**: 平衡成本，减少每次请求的 system prompt token 消耗

**三项优化**:
1. **精简 SKILL_PROMPT_LINES 描述** — 去掉与 RULES_CORE 重复的使用场景说明和触发词示例，只保留接口签名+参数类型+必要约束
2. **精简 RULES_CORE 记忆管理段** — JSON 示例从 3 条多行缩减为 1 行内联格式
3. **SKILLS 条件注入** — 低频 skill（book.*/media.*/habit.*/decision.*/voice.*/deep.*）只在对应 RULES 段被注入时才注入描述。brain.py 中 `_select_rules()` 返回 `(segments, tags)` 元组，tags 传给 `build_skills_prompt(injected_rule_tags=...)`

**量化效果**:
- 最常见场景（普通聊天）: 8422 字符 ~5895 tokens（优化前 10854 字符 ~7597 tokens）
- **总体降幅 22.4%，每次普通聊天省 ~1700 tokens**
- 读书/影视/习惯等场景按需注入，不影响功能完整性

## 对话理解能力修复（已完成 ✅）
**问题**: 用户发送普通对话/提问（如"岁岁能吃花生吗？"），Karvis 不正常回答问题，而是给出文学化的空洞抒情，或错误归档为情感分享

**根因分析（5个叠加缺陷）**：
1. **ignore 语义误导**：描述是"不处理"，LLM 理解为不应选择，被迫匹配归档类 skill
2. **归档偏向过强**：RULES_CORE 明确说"积极分类，只有实在无法归类的才选 ignore"
3. **缺少"对话/提问"意图类别**：优先级排序中没有"对话"作为独立类别
4. **Reflect 防护黑洞**：reflect_pending 时所有非 reflect skill 被强制重路由
5. **SOUL 缺少对话者身份**：LLM 不知道自己可以/应该直接回答问题

**修复内容**：
1. `prompts.py` — ignore skill 重命名为"直接对话回复"
2. `prompts.py` — RULES_CORE 新增"对话、提问与咨询"意图类别（最高频场景）
3. `prompts.py` — 优先级排序中"对话/提问"独立为第5级，高于归档
4. `prompts.py` — 归档规则从"积极分类"改为"谨慎归档"，明确列出不归档的场景
5. `prompts.py` — OUTPUT_FORMAT 增加对话回复的完整 JSON 示例
6. `prompts.py` — SOUL 增加"首先是可以正常对话的朋友"身份定义
7. `prompts.py` — 核心理念增加"默认是对话"和"回答要务实"
8. `brain.py` — Reflect 防护增加 _NO_REROUTE_SKILLS 白名单（ignore/todo/settings等不被重路由）
9. `prompts.py` — 想法与随笔规则增加"分享 vs 提问"的区分示例
